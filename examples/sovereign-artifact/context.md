# Work becomes shared knowledge

This interactive explanation explores a proposed OKF Hub product loop: work
happens, an artifact is created, its meaning is preserved, the team reuses it,
and later work improves it. The subject is our own OKF Hub product direction, so
the explanation is itself an example of the thing we want teams to retain.

## Evidence and accepted direction

- In the product discussion on 4 October 2026, Franck reported strong workplace
  adoption of Claude artifacts for interactive explanations, dashboards, and
  slides. He described the resulting outputs as useful but scattered. This is a
  first-hand qualitative observation, not quantified adoption research.
- Franck agreed with the direction: “work happens, knowledge improves,
  subsequent work gets better.”
- The requested next step was to dogfood the direction with the Codex equivalent
  of artifacts. This explanation was created in response and can run both in the
  conversation and as a standalone HTML file.

## Product hypothesis

OKF Hub could become a shared, sovereign home for the useful things teams create
with AI. Artifacts would be first-class outputs alongside their semantic
context. People could find creations through a subject, see their sources and
ownership, share a stable link, and improve them with another person or agent.

The artifact carries the experience: its interface, logic, assets, and
meaningful data. OKF preserves its purpose, claims, evidence, ownership,
relationships, assumptions, and open questions. The creating agent should
produce both together so people do not have to write a second document.

Sovereignty means retaining the complete useful creation and its context so
another tool or provider can maintain it. For this example the complete creation
is local HTML, embedded styles and JavaScript, and this Markdown context. It has
no external libraries, network requests, or data credentials. Presentation state
consists only of the selected step.

## The five stages

1. **Work happens:** workplace experience reveals useful creations scattered
   across conversations and tools.
2. **Work produces an artifact:** our product conversation becomes this
   interactive explanation, retaining editable code and assets.
3. **OKF preserves the meaning:** the artifact and its purpose, evidence, and
   ownership connect to the same subject.
4. **The team reuses it:** the proposed product flow makes the explanation
   discoverable, shareable, and available with relevant context to a person or
   agent.
5. **The next work gets better:** a later task uses existing assumptions and
   questions, improves the artifact, and records the reason for change.

The diagram is a proposed product loop. It does not establish that team
discovery, sharing, contextual retrieval, or automatic maintenance has already
been implemented or validated.

## Assumptions to validate

- Teams will save a useful creation when doing so adds little effort to their
  existing AI workflow.
- Organising by subject and preserving context will make creations easier to
  find and reuse.
- The creating agent can capture useful context without hiding uncertainty or
  inventing authority.
- Shared ownership and version history will help teams keep artifacts current.
- Existing artifacts and their context will improve a subsequent real task
  enough to justify the workflow.

## Open questions

- Which creation workflow should get the first direct save integration?
- Who confirms claims and owns updates when an agent creates the output?
- What is the smallest metadata set that makes retrieval useful without adding
  maintenance work?
- How should OKF distinguish dashboard snapshots from views backed by live data?
- Which sources changing should trigger a review of an explanation, dashboard,
  or slide deck?
- What evidence from a real team's second use would validate the reuse loop?
